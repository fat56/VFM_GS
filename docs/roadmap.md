## 排队

- Depth Anything 几何先验作为 v2 质量主线排队。正式接入前已验证两个 COLMAP 稀疏几何 proxy：`colmap_depth_edge_l1` 用 SH0/albedo luma edge 与 sparse inverse-depth edge 做 L1 残差，bicycle `-r 8` 30k 为 26.4718 / 0.8164 / 0.1925，PSNR/SSIM 低于 FastGS；`colmap_depth_edge_prior` 直接把稀疏几何边界 cache 作为 densification prior，bicycle `-r 8` 30k 为 26.3488 / 0.8085 / 0.2047、355,994 个点，质量进一步下降。结论是 COLMAP sparse edge 覆盖太稀，两个 proxy 都收束为负结果。下一步若推进几何先验，应直接使用 dense depth prior，例如 Depth Anything 的 scale/shift 或 rank 对齐 depth residual 与 depth-edge protect，而不是继续扫描 COLMAP sparse edge 参数。
- 下一版优先把离线 selector 固化为可复现实验入口，但不能使用 test oracle。短期更可行的方向是：一方面用独立 validation split 或预先固定的数据集级策略评估 selector，另一方面用训练过程信号做保守回退。Tandt 的 staged 自动容量下限、prunemin-only 和 pruning-fusion-off 三条诊断已经证明容量不足、早期 staged target、pruning fusion 都不是单独主因；后续不再继续 Tandt 单点修复支线，直接采用 baseline 回退。随后再把 QCGI 分档接入自适应 density/prune 强度：当候选 `ΔGS < 0.1M` 且 QCGI 为正时保留增长，当 `ΔGS >= 0.1M` 且 QCGI 不足时回退或增强 pruning。
- 大分辨率下一步不继续扩大 DINO 模型。high-res `top-k25 weighted i0.50` 已完成 MipNeRF360 9 场景复验并取得数据集均值正向；treehill/flowers 的 `max` 都确认 descriptor 强度可以修复质量，但容量代价超过 0.1M；treehill `weighted i0.70` 省点但 SSIM/LPIPS 负向，flowers `weighted i0.70` 三项质量负向，stump `weighted i0.35` 和现有 soft budget 都容量失控，说明固定 importance 与只衰减 VFM importance 都不是稳定容量解法。stump staged target 1.15M 证明硬反馈能控制最终点数，但早期大幅裁剪会严重破坏质量；late target 1.18M 进一步证明一次性 final target-prune 不适合 high-res descriptor 容量控制；post-densify staged target 虽然比 final-only 恢复明显，但 24k 单次删除 2M 级 Gaussians 后仍明显低于 baseline；1.45M 早期 staged target 也没有保住质量；warm8000 说明简单缩短 VFM 介入窗口也会转入 2.74M 高容量低效轨迹；densify budget 1.20M 虽把点数降到 2.38M，但质量仍低且远超预算。candidate cap 1.20M/1.35M/1.45M、`spatial_xyz`、`branch_type`、`screen_support` 都能控制点数，但 high-res stump 质量全部低于 FastGS big 和自然 i0.50，说明候选集合末端硬截断会破坏有效 densification 分布。`densify_metric_thresh=6.0` 前置门槛在 stump 上正向：27.1803 / 0.7887 / 0.2340、1,144,519 个点，相对 FastGS big 为 +0.0493 PSNR、+0.0026 SSIM、LPIPS -0.0066，QCGI +0.0513，且增点低于 0.10M；相邻 `densify_metric_thresh=5.5` 在 stump 上 QCGI 为负，不能替代 6.0。bonsai matched 复验进一步显示固定绝对 6.0 不能跨场景泛化：32.5709 / 0.9525 / 0.1587、1,012,191 个点，相对 FastGS big 为 -0.4154 PSNR、+0.0013 SSIM、LPIPS -0.0013，QCGI -0.7601。连续前置门槛不能做成固定全局阈值，下一步转为场景自适应 densification 强度控制。默认关闭的 `densify_budget_curve` 已实现并完成 bicycle 620-step 集成验证，支持 `linear`、`quadratic`、`sqrt` 三种曲线；high-res stump 1.15M sqrt 正式诊断为 27.2129 / 0.7900 / 0.2324、1,163,705 个点，QCGI +0.0935，优于固定 metric6。bonsai 1.08M quadratic max6.0 matched 复验只比固定 metric6 微升但仍明显低于 FastGS big；max5.5 进一步变差到 32.2328 / 0.9494 / 0.1586、1,051,932 个点。结论是 bonsai 负例不是单纯门槛过高，放松门槛只增加点数并伤害质量；停止相邻 metric 阈值扫描。下一步回到自然 `weighted i0.50` 质量正例，或转向 Depth Anything 几何/边界 residual。继续使用 QCGI/ΔGS 门槛约束容量收益。
